## 一、需求定位

系统定位从「销售行为记录与统计分析」走向「以商机发现为核心的销售经营决策」。本 PRD 承接其中**商机发现与经营关注**这一层：从大量客户与销售活动中识别具有明确经营信号的客户候选，回答管理者三个问题：

1. **哪里存在值得推进的商机？** 减少无目的的名单筛选。
2. **为什么值得关注？** 提供拜访、跟进、订单及销售沟通内容等可追溯证据，区分客观事实、业务规则与 AI 推断。
3. **下一步应该做什么？** 围绕客户联系、商机核实、经营阻碍、保护期管理等场景，提供可解释的行动建议。

核心原则：**Opportunity-first, Evidence-backed, Action-oriented.**

## 二、口径红线（不可违反）

- 商机候选**不等于**高成交概率；第一版不生成成交概率、不做客户价值评分。
- 「未发现订单」**不等于**未成交：OA 订单历史仅覆盖接口可获取的最近 365 天，CRM 快照可能滞后，一律表述为「当前可获取数据范围内未发现可靠匹配订单」。
- 「存在订单执行单」**不等于**「合同已签订」：普通订单与代理商订单的合同确认规则需分别验证后才可启用「合同成交」类文案；订单执行单不证明全款到账或实际交付（交付/回款只能从 OA 评论与附件人工判断，识别难度大、不可靠）。本阶段成交相关表述**止步于已验证的事实字段**。
- 客户匹配四态（verified_id / exact_name / ambiguous / unmatched）中，未经确认的候选匹配不自动计入成交或商机事实。
- 系统不在数据缺失或证据不足时生成确定性判断；每条候选必须附证据与数据范围说明。

## 三、第一阶段场景（优先验证，先数据验证再产品化）

| # | 场景 | 信号描述 | 主要数据源 |
|---|---|---|---|
| S1 | 多次拜访但未发现有效订单 | 见下方验证口径（2026-10-21 确认） | visits + oa_orders（四态匹配） |
| S2 | 私海有经营动作但无成交证据 | 私海客户存在明确跟进/拜访动作，暂未发现有效成交证据 | CRM 快照 + visits + oa_orders |
| S3 | 沟通记录中的采购信号 | 拜访总结/跟进纪要中出现明确采购需求、报价、产品数量或计划时间 | PRD-003 客户之声输出的「商机信号候选清单」 |

### S1 验证口径（2026-10-21 产品决策确认）

定义为「**多次拜访、未发现有效订单**」，验证条件：

- 默认观察**近 90 天**；
- 客户在该窗口内**至少 3 次有效拜访**（`NOT exclude_from_visit_count`，占位名按既定口径过滤）；
- 客户身份**可靠关联**（可挂到 CRM 客户或 OA 订单客户的已确认身份）；
- 在**当前 OA 覆盖范围内**未发现可靠匹配的有效订单；
- 匹配不确定（ambiguous/unmatched）与数据覆盖不足（历史补录缺口、订单 365 天缺口）的情况**明确排除或单列**，不混入候选结论。

验证动作：**同时统计近 30 / 60 / 90 天三个窗口的候选数量**，对比名单质量与排除项构成，用于验证「3 次 / 90 天」阈值的合理性，再定稿阈值。

**不得**将候选直接标记为「高价值客户」或「未成交客户」。

第一阶段工作方式是**离线规则验证**：用真实数据跑候选清单 → 人工抽样核对准确率与误报原因 → 再决定产品化形态。「拜访多」只是候选信号，不直接等于高价值，验证报告需给出误报分类。

## 四、第二阶段场景（研究储备，条件满足后推进）

- 外勤地点周边 10km 公海线索（依赖客户坐标准确性、公私海实时归属与领取权限核实）；
- 代理商长期缺少跟进记录；
- 直营与代理商即将掉保客户（依赖 PRD-006 保护期规则核实，全部待业务确认）；**2026-10-23 数据核查**：CRM MCP 的 `latest_recycle_time` 经实测为「预计掉保截止日」（大量未来日期），非历史掉保事件，历史事件应看 `latest_return_pool_time`；字段可用但保护期天数规则（直营 15 天/代理商 2 个月）是否即该字段的计算口径**仍待业务书面确认**，确认前不做掉保提醒产品化（详见 `docs/crm-mcp-audit-2026-10-23.md`）；
- 僵化客户与销售资源投入异常。

## 五、MVP 输出形态（2026-10-21 产品决策确认）

- **使用者**：第一版面向**管理端**，保持现有 **admin-only** 权限，不提前下放。
- **输出**：商机候选清单，每条包含——**推荐原因**（命中哪条规则）、**事实依据**（拜访/跟进/订单记录与原文引用）、**数据时间范围**（观察窗口与数据覆盖说明）、**详情入口**（跳客户详情证据页，接 PRD-008 Phase 2）。
- **最小反馈机制**（三态）：`值得跟进` / `暂不相关` / `待核查`。反馈用于迭代规则质量，需落库留痕。
- **暂不做**：自动派单、钉钉推送、复杂商机评分；不生成成交概率；不以 AI 单次输出触发客户归属变更或考核。
- 与 PRD-008 Phase 2 联动：从候选清单带上下文下钻到客户详情证据页。

## 六、依赖与启动条件

- OA 订单 V1 已完成本地验收，**线上部署与增量验收待完成**（S1/S2 的事实源）；

- 客户匹配可信度与覆盖范围保障（PRD-006 第一阶段，P0）决定候选清单的准确率上限；
- 保护期/公私海规则（2026-10-08 会议结论，见 PRD-006）**全部待业务核实**，核实前不做掉保提醒类产品化。

## 七、决策记录

**2026-10-21 已确认：**

- S1 验证口径（近 90 天 / ≥3 次有效拜访 / 身份可靠关联 / 排除与单列不确定项 / 同步统计 30-60-90 天）；
- MVP 面向管理端 admin-only，输出候选清单（推荐原因/事实依据/数据时间范围/详情入口）+ 三态最小反馈；
- 暂不做自动派单、钉钉推送、复杂商机评分。

**仍待确认：**

1. 第二阶段 10km 公海线索的可见范围与撞单顾虑（见 2026-10-08 讨论清单遗留问题）；
2. 候选清单反馈数据的复盘节奏（谁看、多久看一次、如何用于阈值迭代）；
3. S2/S3 进入候选清单的先后顺序与合并展示方式。
