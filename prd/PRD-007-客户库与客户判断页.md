# PRD-007 客户库与客户判断页

> 状态：V1（只读、admin-only）已实施（2026-10-19）；V2 需求设计中（见第七节）
> 关联：上游数据依赖 [PRD-006-客户同步与生命周期经营](PRD-006-客户同步与生命周期经营.md)；闭环编排见 [PRD-002-客户侧数据闭环](PRD-002-客户侧数据闭环.md)；下钻链路与入口设计见 [PRD-008](PRD-008-客户模块IA与分析下钻V2.md)（已拆分：导航与 IA 属 Phase 1，下钻联动属 Phase 2，数据验收后实施）

## 一、定位

**insight-first, record-second。** 客户判断页不是 CRM 的字段复制品：

- CRM（探迹）回答「这个客户的档案是什么」；
- 本模块回答「这个客户现在处于什么状态、系统观察到了什么」——把 CRM 跟进、外勤实际拜访、未来 OA 订单三条事实线放在同一个客户身上对照。

第一版只做读取与呈现，不做客户编辑、不做 CRM 回写。

## 二、用户与权限

- **第一版 admin-only**：详情页包含联系人、电话、地址、竞争对手等敏感信息，非 admin 的可见范围与字段脱敏规则尚未决策，先按管理员本地验证。
- 后续决策项（未做）：manager/staff 的可见范围收敛、字段级脱敏（电话/地址/竞争对手）、是否开放给区总做教练场景。

## 三、功能范围

### 3.1 客户列表（/customers）

- 筛选：关键词（客户名模糊）、客户类型（国内企业/国内代理商/海外终端/海外代理商）、公私海、负责人、跟进阶段。
- 列：客户名称（点击进详情）、类型、公私海、阶段、负责人、区域、跟进次数、最近跟进、数据状态（审批中）。
- 客户与代理商不拆两套页面，用「客户类型」区分。
- 页面必须展示 **CRM 数据快照日期**（最近一次手工导入批次时间），避免误解为实时数据。

### 3.2 客户判断详情（/customers/:id）

布局原则：**左侧大区域放系统整合后产生的判断、关系和时间线；右侧窄栏放 CRM 基础资料与原始信息。** 模块整体白底，桌面端左 70% / 右 30%，移动端上下堆叠。

左侧（分析区）：

1. **关键判断**：跟进×拜访关系（都有/只跟不访/只访不跟/都没有）、跟进次数、实际拜访次数、最近跟进/拜访时间、信号标签（超 30 天未跟进、超 30 天未拜访、审批中）。
2. **跟进 × 外勤 × 订单链路**：CRM 跟进、实际拜访（外勤签到）、OA 订单三段关系并排对照。
3. **动态时间线**：CRM 跟进记录与实际拜访记录合并按时间倒序。
4. **订单执行**：空状态，明确「待 OA 订单同步接入」——不展示任何假订单数据。

右侧（事实区）：

1. **Basic Info**：类型、公私海、阶段、负责人、区域、渠道、地址、装机地址、法人、竞争对手、标签、快照时间。
2. **联系人**：姓名、职务、是否决策人、电话。
3. **原始 CRM 字段**：`extra` 折叠展示，满足查原始信息但不抢占主视觉。

## 四、数据口径

- **实际拜访匹配**：visits 客户名 `splitRealCustomerNames` 拆占位名 → `normalizeCustomerName` 归一化 → `resolveCrmName` 三层匹配（精确 → 去分支后缀 → 双向包含）到该客户 `name_norm`；排除 `exclude_from_visit_count` 行。与 `/crm-analytics/cross`、`stuck` 同一口径。
- **联系人/跟进关联**：`crm_contacts` 按 `customer_name` 与客户名桥接；`crm_follow_records` 按 `customer_name_norm` 桥接（空值行回退客户名）。当前是名称桥接，**待 PRD-006 统一客户身份层落地后改为 ID 关联**，本次不做数据库迁移。
- **订单**：后端固定返回 `orders: []` + `orders_status: "pending_oa_sync"`，前端结构先稳定；成交事实未来以 OA 两张订单执行单为准。

## 五、明确不做（本次）

- 不接 OA 订单同步、不建订单表；
- 不做客户编辑、CRM 回写；
- 不建统一客户 ID/人工确认表（PRD-006 身份层）；
- 不做非 admin 的字段级权限与脱敏；
- 不复制 CRM 完整静态字段页作为主体内容。

## 六、验收指标

- admin 导航出现「客户库」；非 admin 导航不可见、直访跳回首页、接口 403。
- 列表搜索/筛选/分页可用，快照日期可见。
- 详情页白底、左分析右资料；跟进/拜访/联系人数据正确；订单区显示「待 OA 订单同步接入」而非假数据。

## 七、V2 规划（2026-10-19 新增，优先级 P0）

在已实施的 V1（只读、admin-only）基础上：

1. **客户库保留基础表格定位**，不变成重型 CRM；
2. **优化默认字段与可选字段**（列配置：默认精简，可按需展开）；
3. **增加 CRM 跟进与实际拜访的必要对照字段**（如跟进次数 / 实际拜访次数 / 最近跟进 / 最近拜访 / 匹配状态），列表层即可发现「只跟不访 / 只访不跟」；
4. **支持从客户分析带入筛选上下文进入客户库**（如「躺尸客户」「公海挽回高阶段」一键落到对应筛选的客户列表，与 PRD-008 下钻链路配合）；
5. 进入客户详情后可查看 CRM 跟进、外勤拜访、联系人等事实记录（V1 已具备，V2 补齐「拜访记录 → 原始签到详情」追溯）；
6. **保留 CRM 原始字段（extra）折叠区域**；
7. **订单继续显示「待 OA 接入」状态**，不展示假数据；
8. **保留当前 admin-only 权限边界**，不提前扩大敏感信息访问范围；非 admin 的可见范围与脱敏规则仍待决策。

V2 明确不做：客户编辑 / CRM 回写 / 非 admin 权限放开 / 统一客户 ID 建表（属 PRD-006 第一阶段，落地后再把名称桥接改为 ID 关联）。
