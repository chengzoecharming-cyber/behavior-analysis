# PRD-008 客户模块 IA 与分析下钻 V2

> 状态：**Phase 1 已完成**（2026-10-19 Sidebar + App Shell 上线，可折叠左侧导航与全局 Layout 首轮重构完成）；**Phase 2 进行中（需求设计）**——后续围绕「经营事项下钻」推进，与 [PRD-009](PRD-009-商机发现与经营关注.md) 配合分阶段实施，不再做无目标的全局 UI 重构｜ 创建：2026-10-19 ｜ 优先级：P0
> 关联：[PRD-007-客户库与客户判断页](PRD-007-客户库与客户判断页.md)、[PRD-006](PRD-006-客户同步与生命周期经营.md)（匹配口径与身份层）、[PRD-002](PRD-002-客户侧数据闭环.md)（闭环编排）、[PRD-009](PRD-009-商机发现与经营关注.md)（经营事项与商机候选，Phase 2 下钻的业务来源）

## 一、核心目标

打通「**客户分析 → 客户列表/客户详情 → 原始记录**」的业务路径：客户分析负责发现问题，客户库负责找到客户，客户详情负责追溯事实与解释判断。

## 二、阶段拆分（2026-10-19 调整）

当前存在三项数据依赖，决定分两阶段实施：

1. 历史销售外勤 OA 审批单尚未完全补录（PRD-001 进行中）；
2. 「订单执行」「【代理商】订单执行」两类 OA 表单正在接入（PRD-002/006）；
3. 客户身份统一与跨源匹配的准确性还需验证（PRD-006 第一阶段）。

因此：**依赖完整跨源数据的业务判断扩展与下钻开发暂停到数据验收后，但客户模块建设（导航与 IA）不暂停。**

### Phase 1：全局导航与客户模块 IA（现在实施）

只做结构，不做新业务判断：

- 顶部导航改为可折叠左侧 Sidebar（桌面端展开约 208–224px，折叠约 56–64px）；
- 保留现有一级业务模块与导航权限（admin-only 入口、角色收敛规则不变）；
- 保留外勤分析（ConsolePage）现有功能、图表和交互，**不重构内部页面**；
- 整理客户分析现有 Tabs 的职责、命名和层级（不改数据口径）；
- 保留客户库作为基础检索与记录入口（V1 能力不变）；
- 客户详情保持现有业务逻辑和数据展示；
- 统一各页面布局容器，确保宽屏表格、地图和图表不被 Sidebar 破坏。

### Phase 2：客户分析下钻与跨源闭环（围绕经营事项分阶段推进）

- 客户分析指标 → 客户集合 → 客户详情 的下钻链路；
- CRM 跟进、实际拜访与 OA 订单的关联展示；
- 数据时间范围、同步状态、客户匹配置信度、原始记录追溯的统一展示；
- 根据真实数据补充客户经营信号，**不新增未经验证的业务判断**。

Phase 2 推进方式（2026-10-21 决策确认）：**允许按功能分阶段实施，不再以所有历史数据补录完成作为统一启动条件。** 每项下钻能力以 PRD-009 商机候选/经营关注场景为业务来源，从候选清单/关注事项带上下文进入客户详情证据页；数据覆盖范围与匹配状态必须随页面明示。**但任何正式经营判断（对外输出结论性口径）必须满足其对应的数据覆盖、客户匹配及业务口径验收条件**——原三项启动条件（历史补录约定覆盖、订单 OA 线上部署与增量验收、跨源匹配准确率人工抽检）保留为该门槛。

## 三、Phase 1 详细方案

### 3.1 页面 IA（目标结构）

```text
Sidebar
├── 总览                    /
├── 外勤分析                /console        （原「数据&分析」，保持现状不重构）
├── 客户分析                /customer-analysis
├── 客户库                  /customers      （admin-only）
└── 系统管理                （分组，admin-only）
    ├── 数据同步            /sync
    ├── 同步中心            /sync-center
    └── 规则配置            /rules

用户菜单（头像/底部）：用户管理 /users（admin、manager）、反馈与申诉 /feedback、退出登录
独立路由（不占菜单）：/customers/:id 客户详情（高亮「客户库」）、/report/:token 免登录战报
```

- 权限沿用现状：客户库、数据同步、同步中心、规则配置仅 admin 可见；客户分析所有登录角色可见；外勤分析、总览所有角色可见。**本阶段不改任何权限判断。**
- 移动端（<768px）：沿用抽屉式导航，入口集合与 Sidebar 一致。
- 「数据&分析」更名为「外勤分析」仅为菜单命名调整，路由 `/console` 保持不变（避免改书签与代码引用）。

### 3.2 客户分析 Tabs 整理

现有 7 块：总览 / 交叉分析 / 词云 / 躺尸卡死 / 机会地图 / 公海挽回 / 私海健康度。Phase 1 只做命名与职责文案梳理（Tab 标题、副标题说明），不改口径、不合并、不新增下钻；输出 Tab 职责矩阵随 PR 一并评审，重复内容的处置结论留给 Phase 2 设计输入。菜单「客户分析(WIP)」去掉 WIP 后缀。

### 3.3 布局容器统一

- 现顶部导航内有 `max-w-7xl` 容器；改 Sidebar 后内容区横向变宽，需统一页面容器规则：默认内容区 `max-w-[1400px]`（或保持各页现状取其并集）+ 统一 padding；
- 重点回归页面：ConsolePage（地图 + 宽表格）、CustomerAnalysisPage（多 Statistic + 宽 Table）、CustomersPage / CustomerDetailPage（白底模块，现有 `isCustomerModule` 灰底覆盖逻辑需随布局迁移）、DecisionPage（驾驶舱图表）、HeatMapContainer / CustomerMap / MapContainer（地图容器宽度自适应）；
- Sidebar 折叠/展开切换时地图组件需 resize（高德地图在容器尺寸变化后需触发 `resize`，否则留白或偏移）。

### 3.4 Phase 1 需要修改的文件（预计）

| 文件 | 改动 |
|---|---|
| `frontend/src/App.tsx` | 顶部 Header 导航 → 左侧可折叠 Sidebar（含分组、折叠态、移动端抽屉复用）；菜单项重命名与分组；`isCustomerModule` 白底逻辑随布局调整 |
| `frontend/src/components/AppSidebar.tsx`（新增） | Sidebar 组件：菜单分组、折叠交互、激活高亮（含 `/customers/:id` 归属高亮）、权限过滤（从 App.tsx 迁入 `visibleNavItems` 逻辑） |
| `frontend/src/pages/CustomerAnalysisPage.tsx` | Tab 命名/职责文案梳理；页面容器宽度适配 |
| `frontend/src/pages/ConsolePage.tsx` | 仅容器/宽度适配（如有硬编码 max-width），不动功能 |
| `frontend/src/pages/DecisionPage.tsx` | 仅容器/宽度适配 |
| `frontend/src/pages/CustomersPage.tsx` / `CustomerDetailPage.tsx` | 白底容器适配新布局（替代 `isCustomerModule` 特判） |
| `frontend/src/components/MapContainer.tsx` / `HeatMapContainer.tsx` / `crm/CustomerMap.tsx` | 容器尺寸变化时触发地图 resize |
| `frontend/src/hooks/`（如新增） | 可选：`useSidebarCollapsed` 状态（localStorage 持久化折叠偏好） |

后端无改动；路由路径全部不变。

### 3.5 Phase 1 验收

- 桌面端 Sidebar 展开/折叠正常，折叠偏好刷新后保留；
- 各角色看到的菜单与现状一致（admin 全量 / manager、staff 收敛）；
- 外勤分析、决策页所有图表、地图、宽表格在新布局下无横向挤压、无破版；
- 客户分析 Tab 命名与职责文案更新，数据与交互不变；
- 客户库列表/详情白底展示正常；`/customers/:id` 时 Sidebar 高亮「客户库」；
- 移动端抽屉导航可用，入口与 Sidebar 一致。

## 四、Phase 2 范围备忘（数据验收后细化，当前不实施）

- 分析表格 → 客户详情跳转（来源上下文 + 返回恢复）；
- 总览指标 → 客户集合（URL 参数化筛选落到客户库）；
- 客户库统一检索筛选增强 + 跟进×拜访对照列（PRD-007 V2 同步实施）；
- 数据时间范围 / 同步状态 / 匹配置信度 / 原始记录追溯统一展示；
- 待确认桶与未匹配客户清单的处理动作；
- 基于真实数据补充客户经营信号；不新增未经验证的业务判断、评分或预测。

## 五、明确不做（两阶段通用）

- 不新增客户价值评分、成交概率预测、无依据的健康分数；
- 不做复杂 Agent / 自动决策；
- 不做统一客户 ID 建表与人工确认工作流（PRD-006 第一阶段）；
- Phase 1 不动外勤分析内部页面、不改权限、不改数据口径；
- 不放开客户域权限边界（维持 admin-only，见 PRD-007）。
