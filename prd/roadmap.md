> 本文件仅维护产品定位、模块边界、需求分类、优先级、实施状态及 PRD 索引。具体规则、技术方案与验收标准以各 PRD 为准。
>
> 状态口径：✅ 已完成 / 🔵 进行中 / ⏸ 暂停 / ⚪ 未开始。
>
> 优先级口径：P0 当前优先推进 / P1 下一阶段 / P2 后续规划。
>
> 最后更新：2026-10-21。

## 一、产品定位

**从销售行为记录与统计分析，走向以商机发现为核心的销售经营决策系统。**

系统整合钉钉外勤拜访、CRM 客户与跟进记录、OA 订单执行等数据，帮助销售管理者回答三个问题：

1. **哪里存在值得推进的商机？** 从大量客户与销售活动中识别具有明确经营信号的客户，减少无目的的名单筛选。
2. **为什么值得关注？** 提供拜访、跟进、订单及销售沟通内容等可追溯证据，区分客观事实、业务规则与 AI 推断。
3. **下一步应该做什么？** 围绕客户联系、商机核实、经营阻碍、保护期管理等场景，提供可解释的行动建议。

核心原则：

**Opportunity-first, Evidence-backed, Action-oriented.**

商机候选不等于高成交概率；未发现订单不等于未成交；存在订单执行单不等于合同已签订；系统不在数据缺失或证据不足时生成确定性判断。

## 二、产品模块与边界

| 模块 | 核心职责 | 当前方向 |
|---|---|---|
| 总览 | 公司级 Dashboard，汇总外勤执行、客户经营与重点关注事项 | 保留现有功能，后续逐步增加客户经营摘要 |
| 外勤分析 | 拜访、轨迹、区域、员工与销售执行分析 | 保留现有功能；局部增加客户订单状态 Tag 与 Quick Preview |
| 客户分析 | 以商机发现和经营关注为核心，识别值得推进的客户、共性阻碍与异常信号 | V2 逐步从静态 BI 转向行动导向的经营分析 |
| 客户库 | 完整客户索引、搜索、筛选与基础资料查询 | 保留基础记录页，不重复建设分析 Dashboard |
| 客户详情 | 客户经营证据、CRM 跟进、外勤拜访、OA 订单与历史记录追溯 | 支持从经营事项带上下文进入，兼顾日常核查与审计 |
| 系统管理 | 数据同步、规则配置、数据质量与权限 | 持续维护，不作为本轮业务功能重点 |

### PRD-009 初始场景

第一阶段优先验证：

- 多次拜访（默认近 90 天、至少 3 次有效拜访；阈值验证中，同时统计 30/60/90 天候选数量）但未发现有效 OA 订单的客户；不得直接标记为「高价值客户」或「未成交客户」。
- 私海客户中存在明确经营动作、但暂未发现有效成交证据的候选客户。
- 有明确采购需求、报价、产品数量或计划时间的销售沟通记录（与 PRD-003 联动）。

第二阶段研究：

- 外勤地点周边 10km 公海线索。
- 代理商长期缺少跟进记录。
- 直营与代理商即将掉保客户（保护期规则待业务核实）。
- 僵化客户与销售资源投入异常。

上述场景均需明确业务口径与数据范围。「拜访多」只是候选信号，不直接等于高价值；「无 OA 订单」必须表述为当前可获取数据范围内未发现可靠匹配订单。

### PRD-003 MVP 的两个输出

1. **客户之声主题报告**：跨客户归纳集中诉求、产品问题、采购阻碍、竞品反馈及变化趋势。
2. **商机信号候选清单**：从具体沟通记录中提取采购产品、数量、预算、时间、明确下一步动作等信号，并附原文证据。

必须区分销售记录、客户原话及 AI 推断。

第一版不生成成交概率，不自动将文本中的意向认定为确定商机。AI 输出先人工抽样评测，再考虑用于正式推荐和推送。

## 七、关键业务规则与依赖

以下来自 2026-10-08 业务会议，属于待核实规则或场景，不直接视为已上线系统规则。

| 规则/场景 | 当前记录 | 后续处理 |
|---|---|---|
| 直营客户保护期 | 15 天未有效跟进可能掉入公海；7 天内不能重新领取同一客户 | 核实起算时间、有效跟进定义与例外情况 |
| 代理商保护期 | 约 2 个月；第 57 天提醒；续保需提供证据；15 天内不能重新领取同一客户 | 核实具体天数、续保证据与 CRM 实际状态 |
| 公海领取 | 直营公海可直接领取，供应商/代理商公海不可直接领取 | 核实权限及操作流程 |
| 协同跟进 | 主负责人与协同人可能同时持有客户；掉保按主负责人及业务类型判断 | 核实影响保护期的角色与规则 |
| 10km 公海线索 | 根据外勤位置发现附近可拓展客户 | 依赖客户坐标准确性、实时归属和领取权限 |
| 跟进图片重复 | 可能提示跟进记录真实性问题 | 归入质量/审计候选，不作为商机推荐核心 |
| 已交付判断 | OA 订单执行存在日期、图片和流程记录 | 当前只能展示交付相关证据，不能确认为已交付 |

核实路径（2026-10-21 决策）：优先向 CRM 管理员或销售运营负责人书面确认；存在真实历史掉保记录时抽样验证；CRM 单次快照不足以反推完整保护规则时明确标注限制；本阶段不开发自动掉保提醒或自动公海领取。

### 主要依赖

- OA 订单 V1 已完成本地验收，正式线上部署与增量调度仍待验收。
- CRM 手工快照可能滞后，新客户与公私海状态不保证实时准确。
- 外勤历史补录尚未全部完成，未发现拜访不等于实际没有拜访。
- 客户匹配需区分 verified、exact、ambiguous、unmatched；未经确认的候选匹配不自动计入成交或商机事实。
- 代理商订单必须区分终端客户、代理商和签约主体，避免重复统计。
- 「存在订单执行单」不直接等同于「合同已签订」；普通订单与代理商订单的合同确认规则需分别验证。

## 八、下一阶段交付顺序

| 阶段 | 主要交付 | 验收重点 |
|---|---|---|
| 1. 立即启动 | 外勤订单 Tag / Quick Preview；商机 V1 数据验证（30/60/90 天候选统计）；客户之声样本实验 | 真实关联、状态准确、可追溯证据 |
| 2. 验证后实施 | 商机候选清单（admin-only + 三态反馈）、管理者关注事项、客户详情上下文下钻 | 管理者知道为何关注、能采取什么行动 |
| 3. 数据条件满足后 | 10km 公海线索、保护期提醒、代理商维护场景 | 业务规则、归属权限与数据时效正确 |
| 4. 后续扩展 | 客户生命周期、智能推送、订单履约深化 | 可信数据、可解释判断与实际业务反馈 |

本阶段优先验证真实经营价值，不为增加页面数量或指标数量而开发。

## 九、明确不做

- 不开发机加云、刀具柜、智能柜、数字孪生或通用报表查询层。
- 不推翻现有外勤轨迹、地图、里程及 Dashboard 功能。
- 不将客户分析首页继续扩展成大量无行动价值的静态 KPI。
- 不在当前数据条件下开发成交概率预测、无依据的客户健康评分或复杂 Agent。
- 不把 OA 审批通过、ERP 下推、交付资料齐全直接等同于实际发货、交付或验收；不把「存在订单执行单」直接等同于「合同已签订」。
- 不在 CRM 快照滞后的条件下自动领取公海客户或自动修改保护期；本阶段不开发自动掉保提醒。
- 不以 AI 单次输出直接触发客户归属变更、经营结论或员工考核。
