## 一、背景与目标

系统此前只有 2026-06-01 之后的拜访数据。v1 表单「（旧版报销用）用车里程登记&客户签到」实际 **2024-09-13** 就有数据。补录全部历史，目标：

- 控制台可回看 2024-09 起任意一天的轨迹、停留点、风险分；
- 为客户×拜访交叉分析（PRD-002）、客户之声（PRD-003）提供完整历史语料；
- 与钉钉源端逐月对账一致，不产生重复。

## 三、Excel 段实施方案

### 3.1 数据源

- 源文件：`~/Documents/作业/丹弗/地图/` 下 2 个钉钉后台导出 Excel，多 sheet 按模板版本划分。
- 解析注意：openpyxl 需 `reset_dimensions()`，否则读到假的空 sheet。
- 解析产物：`tmp/excel-export-parsed.json`（2026-10-16 生成）。

### 3.2 数据画像（解析后实测）

- 审批单 **7363** 张，月份分布 2024-09（448）~ 2025-10（451），中间每月约 450–610 张。
- 状态分布：完成 7038 / 审批中 262 / 已撤销 53 / 已修改 10。
- 清洗口径：排除已撤销与 0 打卡点单后 → **7119 张有效单、18747 个打卡点、9139 个唯一地址**。
- 状态映射：「已撤销」不入库；「审批中」按 RUNNING 入库；「已修改」按 COMPLETED 入库。

### 3.3 解析与口径（已验证）

- 审批编号 = 钉钉 `approval_id`，与 API 段共用 `processParsedVisits` 防重链路，**重叠 289 张单自动跳过**（已与 API 记录逐字段验证：时间/地址/客户名 289/289 一致）。
- 客户名归属遵循 v1 口径：两站之间填写的客户属于**下一站**（向前挂）。
- `source` 传 `dingtalk` 以复用「审批单级归日」口径；`source_detail='excel-export'` 标记真实来源。

### 3.4 管线三步（`backend/scripts/importDingtalkExcelExport.ts`）

```bash
cd backend
npx ts-node scripts/importDingtalkExcelExport.ts --dry            # 只解析+统计，不写库不调高德
npx ts-node scripts/importDingtalkExcelExport.ts --geocode <N>    # 只做地理编码（限 N 次），结果落 tmp/geocode-cache.json
npx ts-node scripts/importDingtalkExcelExport.ts --import         # 用缓存坐标入库（幂等，可重跑）
```

执行位置约定：

- **`--dry` / `--geocode` 在本地跑**：Excel 源文件在本机，用本地 `backend/.env` 的高德 Web 服务 Key，坐标结果落本地缓存。
- **`--import` 连线上库执行**（参考 API 段做法：脚本与数据传入服务器后端容器 `/app` 执行，或本地经隧道连线上库）；执行前必须先 `--dry` 出统计并经负责人确认，且先做生产备份。

### 3.5 地理编码进度与质量关卡（已完结）

- 最终：9139 个唯一地址，成功 9118（99.77%），21 个无解（无标准 POI 的村庄/公司名写法）转 PRD-005 人工兜底。
- 执行：本地分批（10-19 首批 4000；10-20/21 续跑剩余），`--redo` 复核批次同时覆盖 68 个前缀救回地址的跑偏校验。
- 配额约束：本地高德 Key 每日约 4000 次上限，**按天分批跑，不与线上同步抢配额**（线上同步用服务器 Key）。
- 坐标质量问题统一收口到 [PRD-005-数据清洗专题](PRD-005-数据清洗专题.md)。

### 3.6 入库后派生数据

`--import`（幂等）完成后依次执行：

1. 补算 stops（`computeAndPersistStops`，按 user+date）；
2. routes 分批补齐（`fillMissingRoutes N`，限流）；routes 剩余约 2573 个 user+date，含单点日（永远补不出，最终以对账数为准）；
3. routes 补齐后统一重算异常 + 风险摘要（按「派生数据重算原则」）。

## 四、验收标准
