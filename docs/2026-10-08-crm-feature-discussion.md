# 客户管理模块 · 功能讨论清单（2026-10-08）

> 用途：与相关负责人对齐客户管理方向。前半是功能灵感清单（均基于现有数据可实现性评估），后半是需要对方拍板的问题。

## 〇、现状速览

- **数据**：探迹 CRM 手工 Excel 导入（快照）。已有字段：客户阶段（初步接触→已交付 7 档）、公私海、负责人、掉保历史、渠道、竞品、标签、公司/安装地址（坐标已解析落库）、跟进次数、最近跟进时间、跟进纪要全文、联系人（含决策人电话）、可关联本系统拜访记录。
- **已有功能**：客户分析看板（总览 / 客户×拜访交叉 / 沟通词云 / 躺尸与审批卡死 / 公海挽回 / 私海健康度 / 机会地图）+ 每周一群机器人 CRM 摘要推送（灰度接收人）。
- **空白**：没有任何"给销售本人用"的功能——无附近客户、无主动提醒、无客户详情页；联系人数据导了但未展示；跟进记录只喂了词云。

## 〇.五、已明确的定位（本次补充）

1. **不需要实时**：快照数据即可，不追求探迹 API 实时对接。手工导入节奏 + 页面展示数据快照日期就够。
2. **核心受众是管理层/销售管理者**，不是一线销售自助工具：系统用来**发现销售行为问题**，并支撑管理者**给具体区域的具体人下量化指标**。
3. **空间维度是重点**：机会地图 + LBS + 周围客户，围绕"客户在哪、人在哪、该去哪"展开。

## 一、功能灵感清单

### A. 空间维度：机会地图 + LBS（本次确认的重点方向）

| # | 功能 | 说明 | 实现基础 |
|---|------|------|----------|
| A1 | 机会地图增强 | 现有机会地图（私海蓝/公海橙、气泡=拜访次数）之上：叠加阶段筛选、热力模式、与拜访热力对照（客户在哪 vs 人去哪） | 已有基础，增量开发 |
| A2 | 附近客户（LBS） | 打开应用按当前位置列出 500m / 1km 内客户，显示阶段、负责人、最近跟进/拜访时间。筛选开关：只看无人跟进 / 只看公海（捡漏）/ 全部 | 地址坐标已落库；需新增按半径检索 API |
| A3 | 顺路拜访建议 | 结合当天审批单行程起终点，推荐沿途可顺访客户（优先躺尸边缘、快掉保的） | 有拜访轨迹 + 客户坐标 |
| A4 | 区域覆盖分析 | 按区域看客户密度 vs 实际拜访覆盖，找出"客户多但没人去"的空白区 | 坐标 + region 字段 |

### B. 管理层看销售行为问题（本次确认的重点方向）

| # | 功能 | 说明 |
|---|------|------|
| B1 | 行为×客户交叉诊断 | 在现有「客户×拜访交叉」（只跟不访/只访不跟）上加深：高阶段客户长期无实地拜访、拜访集中少数客户（同客户高频拜访已有）、某区域拜访量异常低等行为信号汇总到管理视图 |
| B2 | 区域/个人拜访覆盖报告 | 按区域+人：负责多少客户、周期内实际拜访多少、覆盖率、未触达客户清单 |
| B3 | 躺尸/掉保追责视图 | 已有躺尸卡死 + 私海健康度，按负责人钻取到具体客户清单，支撑管理谈话 |

### C. 量化指标下达与追踪（本次确认的重点方向）

| # | 功能 | 说明 |
|---|------|------|
| C1 | 指标下达 | 管理者给具体区域的具体人设定周期指标，如：每周新客拜访 X 家、高阶段客户拜访 Y 家、躺尸激活 Z 家、区域覆盖率 W% |
| C2 | 指标达成看板 | 按人展示指标完成进度（实际拜访数据自动对账，不需要销售填报），周/月维度 |
| C3 | 达成推送 | 每周推送个人指标达成情况给本人及其区总（复用现有钉钉机器人通道 + 日报推送机制） |

### D. 主动推送类（复用现有钉钉机器人通道，成本低）

| # | 功能 | 说明 |
|---|------|------|
| D1 | 每周高价值客户推送 | 按人推：名下高阶段但超 N 天未跟进、快掉保（私海 30 天未跟进临界）、公海新退回的高阶段客户 |
| D2 | 掉保预警 | 私海客户距掉保红线剩 7 天时提醒负责人及其区总 |
| D3 | 公海捡漏提醒 | 高阶段客户被退回公海时推给同区域负责人（现有挽回清单仅 admin 可见，可下放） |

### E. 客户详情与基础数据补全

| # | 功能 | 说明 |
|---|------|------|
| E1 | 客户 360 卡片 | 基本信息 + 联系人（决策人标星）+ 跟进时间线 + 本系统拜访历史，一页看完 |
| E2 | 联系人信息展示 | 决策人电话/职位已入库未展示，成本最低的一项 |
| E3 | 客户坐标修正入口 | 地理编码失败/跑偏的客户支持人工修正坐标（visits 已有类似入口） |

## 二、需要负责人确认的问题

1. **指标口径**：量化指标定哪些？（新客拜访数 / 高阶段拜访数 / 躺尸激活数 / 覆盖率…）指标值由管理者手工逐人填，还是系统按区域客户数给默认值？
2. **"高价值"定义**：没有金额/合同额字段，是阶段优先（如方案/报价以上），还是跟进活跃度优先，还是加权？
3. **LBS 使用场景**：附近客户功能主要给谁用——销售自己找客户，还是管理者临时派单（"你附近有个躺尸客户顺便去下"）？这决定做移动端还是管理端。
4. **附近客户可见范围**：销售能否看到别人私海客户？有无撞单顾虑？（默认：可见但标注负责人）
5. **联系人电话权限**：决策人电话给谁看？本人名下全给、他人隐藏？有无飞单顾虑？
6. **行为问题的认定标准**："高阶段客户 N 天无实地拜访算异常"里 N 是多少？哪些行为信号管理层最关心？
7. **使用端形态**：管理端 Web 即可，还是需要钉钉工作台移动入口？
8. **优先级**：A（空间）/ B（行为诊断）/ C（量化指标）三组里先做哪个？

## 三、硬约束备忘（自己心里有数即可）

- 无金额字段 → "高价值"只能用阶段 + 频次推导。
- 快照数据 → 页面统一展示数据快照日期；指标达成按周/月对账即可，不做当日实时。
- 地址坐标解析有失败残留（约 5 次失败后放弃），LBS/机会地图上线前需补一次坐标清洗 + 人工修正入口（E3）。
